# Deliverable 1: Cybersecurity Governance Review Card

## ConnectSphere — Set 1: Professional Event Networking MVP

---

## Cybersecurity Governance Review Card

| Section | Issue / Definition | Impact | Suggested Fix / Mitigation |
|---|---|---|---|
| **1. Confidentiality Risk** | **Unencrypted data transmission (HTTP):** The architecture diagram shows the User's Browser/Mobile App connects to the Web Server via plain HTTP (unencrypted). All PII — including names, emails, phone numbers, company names, and titles — is transmitted in cleartext, violating the **CIA Triad's Confidentiality** principle. This also exposes session tokens and credentials to eavesdropping and man-in-the-middle (MITM) attacks. | **Critical.** Attackers on the same network can intercept sensitive PII in transit using tools like Wireshark. This leads to identity theft, credential harvesting, and regulatory non-compliance with GDPR (Article 32 — encryption of personal data in transit) and CCPA. Loss of investor and user trust is a direct business consequence. | **Implement HTTPS/TLS encryption for all data transmission.** Enforce TLS 1.2+ across all client–server communications. Obtain and install SSL/TLS certificates (e.g., via Let's Encrypt or AWS Certificate Manager). Configure HTTP Strict Transport Security (HSTS) headers to prevent protocol downgrade attacks. Redirect all HTTP traffic to HTTPS at the load balancer level. |
| **2. Integrity Risk** | **SQL injection via unsanitized inputs (No Prepared Statements):** The architecture explicitly notes "SQL Queries: No prepared statements" at the database layer. Combined with the absence of input validation, the application backend passes raw, unsanitized user input directly into SQL queries. This violates the **CIA Triad's Integrity** principle and breaches **Secure SDLC** practices by failing to implement secure coding standards. | **Critical.** An attacker can craft malicious SQL payloads to read, modify, or delete any data in the database — including user PII, event records, and messaging content. In the worst case, an attacker gains full database administrative access, enabling data exfiltration, data tampering, or complete system destruction (e.g., `DROP TABLE`). This constitutes a severe compliance violation under GDPR and undermines the platform's data integrity guarantees. | **Adopt parameterized queries / prepared statements for all database interactions.** Refactor the application backend to use an ORM (e.g., Sequelize, SQLAlchemy) or prepared statements for every database call. Implement multi-layered input validation: whitelist-based validation on the frontend and server-side sanitization on the backend. Deploy a Web Application Firewall (WAF) to detect and block common injection patterns. Integrate static application security testing (SAST) into the CI/CD pipeline to catch injection vulnerabilities before deployment. |
| **3. Availability Risk** | **Publicly accessible admin dashboard with no authentication:** The architecture shows an "Admin Dashboard Access (Public, No Auth)" endpoint, meaning the administrative panel is directly exposed to the internet without any authentication or access control. This violates the **Principle of Least Privilege (PoLP)** — unauthenticated users can access administrative functions intended only for authorized personnel. | **Critical.** Any attacker who discovers the admin dashboard URL can access full administrative capabilities: managing users, modifying event data, altering system configurations, or shutting down services. This can result in unauthorized data access, service disruption (impacting Availability), privilege escalation, and complete platform compromise. It also represents a severe GDPR violation, as personal data is accessible without authorization. | **Implement strong authentication and role-based access control (RBAC) for the admin dashboard.** Restrict admin dashboard access behind multi-factor authentication (MFA). Enforce RBAC so only users with the "Administrator" role can access management functions. Place the admin panel on an internal network or behind a VPN — it should never be publicly accessible. Implement IP whitelisting as an additional layer of defense. Log all admin access attempts for audit trail purposes. |
| **4. Monitoring / Reporting Recommendation** | **Metric to Monitor: Failed Authentication & Unauthorized Access Attempts.** Track the number of failed login attempts, unauthorized API access attempts, and admin dashboard access events per time period. Define this as a composite metric capturing: (a) failed login count per user per hour, (b) requests to admin endpoints from unauthorized IPs, and (c) API calls that return 401/403 status codes. | **Visualization Type: Real-time Line Chart with Threshold-Based Alerting Heatmap.** Use a time-series line chart (e.g., in Grafana or AWS CloudWatch) showing failed auth attempts over time, overlaid with a heatmap by source IP for geographic anomaly detection. Set automated threshold alerts (e.g., >5 failed logins/min triggers investigation). | **Why It Matters:** Without monitoring, ConnectSphere operates blind to active attacks. Real-time visibility into authentication failures and unauthorized access attempts is the foundation of incident response — it enables the team to detect brute-force attacks, credential stuffing, and unauthorized admin access in real time, rather than discovering breaches weeks or months later during an audit. |

---

### Key Cybersecurity Principles Referenced

- **CIA Triad (Confidentiality, Integrity, Availability):** Each risk finding maps directly to one of the three pillars — unencrypted PII (Confidentiality), SQL injection (Integrity), and unauthenticated admin access (Availability).
- **Principle of Least Privilege (PoLP):** The open admin dashboard grants maximum privileges to all users, directly violating PoLP.
- **Secure SDLC:** The absence of prepared statements and input validation indicates that security was not integrated into the development lifecycle — a fundamental Secure SDLC failure.
- **Input Validation:** A cross-cutting concern affecting both Integrity (SQL injection) and Confidentiality (injection-based data exfiltration).
